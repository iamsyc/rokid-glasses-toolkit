# Rokid 眼镜工程

按任务加载仓库中的适配条件、实现说明和操作步骤，在目标设备上完成授权阶段并记录验收证据。参考设备的验证结果不能替代目标设备验收。

## 任务初始化

1. 确定用户目标和现有授权：`overview` 总结/交接，`wifi` 联网，`helper` 安装/开发/媒体，`ota` 工程固件，`root` 提权验证，`optimize` 优化/恢复，`publish` 发布。
2. 从本技能目录执行 `python3 scripts/context.py --task <任务>`，它只定位资料，不联系设备。可从任何目录运行脚本的绝对路径；技能单独安装或目录不明确时加 `--repo /path/to/checkout`。脚本失败时先定位完整仓库，不臆造缺失文件或复用旧电脑路径。
3. 按输出的 `read_files` 阅读设备档案、证据和该阶段文档。故障时读 [诊断经验](references/diagnosis.md)，确认实现时按其中模块表读取源码。进阶到另一阶段时重新选择任务路由，避免漏读对应操作说明。

索引保存于 [任务路由](references/workflows.json)。操作细节以解析出的仓库 `docs/`、`profiles/` 和源码为准，不复制一套漂移的固件哈希或刷写命令到技能正文。

## 已有结论和适配条件

参考设备：RG-glasses / glasses / neo，Android 12 API 32，消费版 `1.27.009-20261014-150203`，工程版 `1.28.001-20261020-150101`。测试前 bootloader 已为 unlocked/orange，验证流程未执行解锁。完整指纹、文件/证书/APK 哈希从设备档案读取。

参考设备已验证：消费版开机联网修复、助手 1.7、厂家签名 full A/B OTA 安装、UID 0、快照合并完成、诊断日志调整、Light Doze、黑底配色、亮度预设、基线恢复和开机再应用。日期与限制以 `evidence/validated-results.json` 为准。目标设备需重新确认这些条件。

厂家证书提供验签公钥，不能用来签发修改固件。root 来自原厂工程版 `adb root`；助手通过本机已有 TCP ADB 和系统 `su` 执行固定命令。AUTH/STLS 认证固件会使该助手通道停止。工程版已安装时直接验证 root 和助手，跳过重复安装 OTA。

尚未验证：通用首次 ADB 开启、锁定 bootloader、跨地区/硬件 SKU、其他源版本、消费固件回退、手机关机或蓝牙关闭、完整手机语音/蓝牙回归、1.7 有图时完整媒体回归、长期续航。工程 OTA 长期获取仍有缺口。遇到缺口继续调查或交付已能完成的阶段，不扩大成功声明。

## 操作顺序

- 总结、发布准备、离线验包只读仓库/主机文件，无需连接眼镜。
- 设备只读核验使用 `tools/rokid.py doctor --serial <明确目标>`；检查其 JSON 的各个匹配项，命令退出 0 本身不表示匹配。它不自动连接或扫描网络，也不绑定后续刷写目标。
- 助手安装按 `docs/HELPER.md`：先验 APK，保持同包同签名升级，逐项授权并回读，首次打开一次后确认已保存网络。签名冲突时先保全数据，不自动卸载/清数据。
- OTA 按 `docs/OTA.md`：核对同一目标身份、精确源指纹和 boot 状态；用从当前设备取得的信任证书验签精确包；原生 metadata verify 通过；供电/空间/更新和快照状态满足要求；完整上传后设备端哈希一致；最后才原生 update。核对 `kSuccess (0)` 与 `UPDATED_NEED_REBOOT` 后再进入已授权的重启验收。原生 verify 需要临时上传元数据；严格禁止设备写入的任务只做离线部分。
- root 验收是无线重连到同一设备后读取 UID 0，不能以 `userdebug` 字样或 `su` 文件存在替代。`adb root` 会重启 adbd，属于设备改动。重启后 shell UID 2000 本身符合历史行为，可在授权范围内再次 root。
- 优化经助手“系统优化与恢复”应用，读取实际状态，保存快照，验证恢复再按需重应用。首次基线属于当前设备，不能套用他人数据。开机自动应用验收要先于电脑手动 root，避免掩盖自动路径失败。

助手界面可通过可用的 UI 工具操作；仅有 ADB 时可读取当前 UI 层级，定位对应控件再用 input 操作，并回读真实系统状态。控件位置以目标设备当前层级为准，不使用参考设备的固定坐标；图片删除和恢复确认仍遵循当前授权。

## 实施约束与停止条件

沿用当前会话已授权范围，避免重复确认。读取仓库或加载技能不构成刷写授权。“只读”不包括安装/授权、改设置、root/unroot、重启、应用优化或 update。

匹配差异、签名/哈希失败、原生适用性失败、更新状态不明、传输中断、目标身份变化时，停止依赖该检查的写操作，保留错误及当前状态，继续只读诊断。不要修改适配档案以使未知设备假通过；不要 reset-status、擦除、回滚、改 AVB 或用其他固件试错。

保留运行环境已有的网络方案。网络、VPN、ADB 认证和防火墙配置不属于默认部署步骤。单独修改认证时，应说明本机 RootBridge 依赖现有 ADB 行为，并验证替代路径。

不读取或公开签名私钥，不提交个人设备标识或授权 URL。原厂固件/厂商 APK 不在公开工程中。不要把没有稳定下载入口解释成已有可重复的一键部署。

## 验收与交接

按 [验收与报告规则](references/acceptance.md) 读取真正结果。变更主机脚本运行相关离线测试；变更 Android 代码重新编译并区分开发签名和发布签名；设备行为声明需相应实机证据。技能结构可校验，结构通过不等于已经完成独立 agent 或硬件验证。

最终报告应包含目标设备匹配情况、实际执行动作、验收证据、可恢复状态、未完成项和具体原因。保留继续操作所需的设备状态与本地记录路径，不将参考设备的速度、亮度或诊断 CPU 数据用作目标设备的测量结果。
