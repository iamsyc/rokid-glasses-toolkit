# 复现步骤与验收

复现流程分阶段执行，每阶段有独立通过条件。命令均在仓库根目录运行；`GLASSES_IP`、本地 SDK 和固件路径需替换为实际环境中的值。

## 设备核对

在已有 ADB 可用时运行：

```sh
python3 tools/rokid.py doctor --serial 'GLASSES_IP:5555'
```

工具只读取明确列出的产品字段、指纹、boot 状态和当前 ADB UID，不扫描网络、不执行 `adb root`、不安装、不重启。报告不输出序列号、IP、SSID；它也不绑定后续刷写目标，安装前仍要自行核对实际设备。

若设备字段、源指纹或 boot 状态与适配档案不符，将其作为一个新的待验证配置。工程版已安装时只验收已有能力，不重复安装同一 OTA。不要通过修改档案绕过差异。

## 消费固件上的助手

按 [安装文档](HELPER.md) 安装并授权，打开一次，确保原厂保存网络存在。首页能报告真实 ADB 协议；联网页能读取当前网络和网络验证状态。图片功能测试使用专用测试图，不以个人照片作为删除测试对象。

确认具备重新进入 Wi-Fi 设置的操作路径后，再按授权执行重启测试。参考测试条件为手机 App 退出前台、蓝牙保持开启。等待开机及 30/90 秒补查，确认 Wi-Fi 与 ADB 恢复，并检查 90 秒补查未打断连接。失败日志公开前需脱敏；接收广播成功不能替代完整联网验收。

## 工程 OTA 和 root

严格按 [OTA 文档](OTA.md) 分别完成主机哈希/签名、设备元数据适用性、传输校验、安装结果、启动和快照合并检查。消费版安装成功与 root 成功是两个验收条件。

工程版启动后主动执行 `adb root`，无线重连后 `id -u` 应为 `0`。再次重启，先观察 shell UID，再重复 root 验证。不要从 `userdebug` 文件名或存在 `su` 推断实际 root 已经成功。

## 优化及恢复

在助手中手动应用所需优化，读取实际状态：

| 项目 | 已验证优化状态 | 恢复期望 |
| --- | --- | --- |
| vendor.cnss_diag | stopped | 使用目标设备的首次基线 |
| logcatd / 轮转份数 | running / 8 | 使用目标设备的首次基线 |
| Light / Deep Doze | 1 / 0 | 使用目标设备的首次基线 |
| 两个原厂连接包 | 已添加必要豁免 | 撤销本工程新增项，保留原有项 |
| 六个颜色覆盖 | enabled | disabled |
| 亮度预设 | 20% → 50，35% → 89 | 目标设备的原始亮度 |

刷新状态、保存快照，然后执行一次完整恢复并重新读取。核对日志、Doze、白名单、覆盖、亮度、超时、夜间模式和自动联网选择。通过后再应用所需优化。

重启验收必须在电脑尚未执行 `adb root` 前读取助手日志及实际配置，证明开机自动应用可独立完成。之后才验证主机 root。不要把单次重连时长当作性能基准。

## 尚需补充的社区验证

记录设备硬件/地区版本、源指纹、OTA 及证书哈希、boot 状态、安装结果、快照状态、root、重启联网、恢复测试。报告模板见 [兼容性反馈](../.github/ISSUE_TEMPLATE/compatibility.md)。

当前欠缺：第二台相同硬件、锁定 bootloader、不同地区 SKU、初始 ADB 开启、稳定固件下载、手机关机/蓝牙关闭、完整手机语音/相机/蓝牙回归、长时间待机与续航对照、1.7 真正有图时的分享/删除回归。
