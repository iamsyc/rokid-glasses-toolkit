# 实现与验证记录

本文件记录 2026-10-21 单台参考设备的实现过程、故障原因和验证结果。公开资料仅包含脱敏摘要，不包含个人地址、序列号、SSID、签名密钥或原始设备日志。

## 1. 消费固件开机联网修复

厂商 `assistserver` 在启动时根据手机连接状态主动关闭 Wi-Fi，仅设置 Android `wifi_on` 不足以持续恢复。最初助手还能遇到厂商 BroadcastQueue 对第三方应用冷启动的限制。

定向分析实际系统 `services.jar` 后，助手 1.2 使用 targetSdk 25，并为本应用允许 `RUN_IN_BACKGROUND`，开机广播开始成功。此时仍出现关联失败，说明广播成功只解决启动环节。

1.3 记录最后成功的 SSID 和网络编号，开机及 30/90 秒补查中，仅在未连接且不处于关联、认证、DHCP 阶段时恢复已保存网络。1.4 修复后台定位权限和 UID AppOps，并按 SSID 匹配当前配置，适应原厂手机服务删除后重建网络导致的编号变化。不读取或保存 Wi-Fi 密码。

最终在手机 App 从多任务退出、手机蓝牙仍开启的条件下，眼镜重启自动联网，ADB 恢复；90 秒补查未打断已建立的连接。没有常驻保活服务，也没有全局改写厂商联网逻辑。手机关机或蓝牙关闭未验证。

## 2. 助手功能演进

1.0 提供 IP、ADB 协议识别及设置入口。TCP 端口打开与 ADB 协议可用分别呈现，避免误报。

1.5 增加网络状态、互联网验证标记、40 条联网历史、系统设置/权限入口，以及 MediaStore 图片分页，每页 20 张。专门测试图的预览、删除取消和确认删除均在消费固件上通过。分享入口存在，手机实际接收尚未验证。

1.6 增加深色显示和亮度预设。1.7 加入系统优化、实际特权状态、基线保存和恢复，沿用同一包名和签名原位升级，保留应用 UID、权限及联网历史。

## 3. 厂家工程 OTA 与 root

消费固件为 `1.27.009-20261014-150203:user/release-keys`。曾验证原生 OTA 元数据校验会拒绝篡改后的清单，说明验签有效。设备中的证书是验签公钥；取得证书不能用来签发自行修改的固件。

已验证工程 OTA 为 `1.28.001-20261020-150101:userdebug/release-keys`。核验包括 ZIP 整包 CMS、payload/metadata 哈希和签名、AVB 信任链/回滚及分区布局。原生 `update_engine_client --verify` 返回 `Payload is applicable`。

通过已有无线 ADB 上传完整包，眼镜端 SHA-256 与主机一致，再由原生 UpdateEngine 安装。返回 `kSuccess (0)` 和 `UPDATED_NEED_REBOOT`；重启从 `_a` 进入 `_b`，启动成功标志成立，Virtual A/B 快照合并最终为 `none`。

工程版实际允许 `adb root`，重连后 UID 为 0。重启后 adbd 回到 shell UID 2000，再次 `adb root` 可恢复 UID 0。没有获取 OEM 私钥、利用内核漏洞、安装 Magisk 或修改启动镜像。bootloader 在操作前已经报告 unlocked/orange。

## 4. 日志、待机与显示优化

诊断对照：20.92 秒内 `cnss_diag` 使用约 6.55% 单核 CPU，`write_bytes` 增加 6,627,328 字节。停止 `vendor.cnss_diag` 后的 20.66 秒内，该进程不存在，所观察固件/驱动日志大小和 mtime 均未改变。保留 Wi-Fi HAL、`cnss-daemon`、wpa_supplicant 与系统 logcatd；日志轮转份数由 256 降到 8，每份约 2 MiB，历史文件没有删除。这些数据不构成整体 CPU 或续航改善百分比。

启用 Light Doze，保持 Deep Doze 关闭，保留助手豁免，并加入 `com.rokid.os.sprite.assistserver`、`com.rokid.cxrservice`。强制轻度待机时无线 ADB 与 Wi-Fi 可用，验证后清除强制模式。长期摘镜待机仍需对照。

助手改成黑底、较暗绿色文字和描边控件；六个可关闭的 framework fabricated overlay 改变原生设置背景及开关颜色。重启设置进程后截图验证生效。亮度保留 136，20%/35% 预设回读 50/89，恢复原亮度回到 136。没有写物理面板节点；截图不能证明光学亮度已测量。

## 5. 配置恢复与开机应用

系统 `su` 为 root:shell 可执行，普通 APK 直接调用会失败。`RootBridge` 通过工程版已有的本机 TCP ADB，执行助手固定的 `su 0` 命令，不提供任意命令输入框。它依赖当前固件无需认证的本机 ADB，遇到 AUTH/STLS 会停止。

首次应用优化之前保存内部基线。界面支持单独切换日志、待机、系统配色，读取实际状态、保存外部快照和确认恢复。完整恢复测试回到原日志服务与轮转配置、两级 Doze 关闭、六个覆盖关闭、亮度 136、超时 10000ms 和原白名单，再次应用也通过。

开机或应用更新时，根据已保存选择有限重试；同一次启动成功后跳过重复应用。一次重启测试中，配置在启动约 41 秒自动应用，约 62.9 秒无线 ADB 恢复。当时 adbd 仍为 shell UID，无需电脑事先 `adb root`。该时间是单次观察，不能作为启动提速承诺。

恢复基线属于首次优化时的配置，不能覆盖外部工具后来所做的所有变更。恢复前应保留应用数据，先恢复再卸载。恢复优化配置也不会降级固件。
